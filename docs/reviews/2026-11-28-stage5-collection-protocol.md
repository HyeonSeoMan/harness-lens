# 5단계 수집 범위·프로토콜 검수

기준 main: `3d41205`(PR #9~#15 포함), PRD v0.5 §7·§11.1, 읽기 전용 stage5-backlog.

- 오너 결정대로 CI·Git Hook 구성만 수집한다. Orca SOUL·MEMORY는 제외한다. 명령 어휘는 구조적 절차 근거, 활성 Git Hook의 실행 비트·실패 종료 표지는 강제 근거로 사용한다. 실행 결과 없이 CI 설정의 존재만으로 실측 대역을 만들지 않는다. SC·VG의 사유는 `needs_ci_pr_results`로 변경한다. 리포트 담당 워커가 이 코드를 “CI·PR 실행 결과 필요(설정 수집과 별개)”로 표시해야 한다(`client.mjs`는 이 작업에서 수정하지 않음).
- C17: `CLAUDE_SKILL_DIR` 유무로 경로를 정하고, 변수가 없으면 지금 읽은 SKILL.md의 실제 경로를 기준으로 한다. C19: 압축 인벤토리는 키별 또는 겹치지 않는 최대 120줄 단위로 읽고 통째 출력·중복 읽기를 금지한다.
- A5 재검토: 현재 knowledge-base에는 README만 있고 개별 항목이 아직 없다. `knowledgeBaseKeys`는 설치 파일의 필수 목록이 아니라 구성에 대응하는 주제 목록이며, 프로토콜은 없는 항목을 건너뛰도록 명시한다. 따라서 파일 부재를 설치 누락 경고로 바꾸지 않고 이전 “정상” 분류를 유지한다. 지식 문서 확충은 별도 콘텐츠 작업이며 이 범위에서 오너 결정은 필요하지 않다.
- N3: main에 세대 무한 누적·줄 이중 계상이 남아 있었다. 같은 파일·세션의 이전 세대를 한 항목에 합치고 coverage는 최신 세대 줄만 센다. 다른 세션 회전은 별도로 보존한다.
- N4: 중복 제거 키에는 기존에도 만료가 없었다. 원시 응답의 90일 보존 기간과 분리해 누적 상태 수명 동안 보존함을 명세·회귀 테스트로 고정한다. 임의로 만료시키면 정리된 응답·이벤트가 재등장할 때 과다 집계된다.
- N5·파서 버전: 기존 버전 불일치 시 재생성은 이미 있었으나 파서 버전은 3이었다. 이번 세대·coverage 변경에 맞춰 4로 올리고, 구버전 archive를 재사용하지 않으며 원본 삭제 구간 손실 가능성을 `session_state_reset`으로 알린다. `sessions.mjs`의 키 집합 주석도 실제 64비트 비암호 해시 설명으로 고친다.

검증: 합성 픽스처로 수집·축 판정·해시·외부 경계·스키마 및 N3~N5를 회귀 검사한다. DiceForge는 읽기만 하고 산출물은 `/tmp/harness-lens-stage5-scope-validation`에 기록했으며 `prepare --no-sessions --strict-budget`의 압축 인벤토리는 5,499토큰 추정으로 6,000 이내다. 세션을 제외한 수집 범위·압축 입력 검증이며 실측 데이터 수집을 검증한 것은 아니다.

로컬 전체 테스트 93/93 및 번들 일치 검사가 통과했다. 12만 응답·이벤트를 포함한 성능 회귀의 최초 RSS 175.7MiB·1,315ms, 증분 RSS 148.2MiB·298ms로 200MiB·5초 예산 안이었다(이 실행 환경의 관측값).
