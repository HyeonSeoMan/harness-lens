# 추이 범위·득실 검토 후속 구현

PR #21 조사 문서의 후속 구현이다. `sessions.window`의 기존 계약은 유지하고 화면의 “토큰 집계 창” 오표기를 “스캔한 세션 기록 범위(무관·미귀속 포함)”로 고쳤다. 귀속 토큰의 별도 기간 필드는 추가하지 않았다. 미귀속 토큰 행과 archive·귀속 없음까지 새 기간 계약을 만드는 작업은 이 수정에 필요하지 않다.

일별 컨텍스트 추이는 귀속된 프로젝트·워커 메인 스레드 기록이 시작된 날부터 관측일만 표시하므로 전체 스캔 범위보다 짧을 수 있다. 이 설명을 리포트에 추가했다. 분포 날짜·archive 일별 요약·두 p90 표본 차이 설명은 유지한다. 구성 시각이 없는 축 지표도 전체 스캔 범위와 같다고 표시하지 않으며, 구성 시각 제한 없이 지표별 표본을 쓴다고 적는다.

분석 프로토콜은 전체 구성 요소 후보 검토, 영향이 큰 후보 우선 검토, Hook 이벤트·강제 방식 구분, 양쪽 근거가 있는 득실만 선별, `limitations`에 생략 후보 ID와 사유 기록을 요구한다. 기존 문자열 배열로 기록할 수 있어 interpretation 스키마는 바꾸지 않았다. 후보 수나 득실 개수를 점수로 삼지 않는다.

## 합성 Hook 10개 수동 검토

임시 `harness-before` 프로젝트에 아래 이벤트·matcher별 Hook 10개를 넣고 `prepare --no-sessions`로 인벤토리를 생성했다. 설정과 스크립트는 임시 경로에만 쓰고 삭제했다. Hook을 실행하지 않았고 실제 프로젝트·사용자 설정·세션 원본은 수정하지 않았다. 아래는 개정 프로토콜의 선별·생략 규칙을 사람이 적용한 검토이며 별도 모델을 실행한 회귀 검증은 아니다.

합성 스크립트는 `gate.mjs`의 `process.exit(2)`, `stop.mjs`의 `// npm test`와 `process.exit(2)`, `validate.mjs`의 `// npm test`, `context.mjs`의 고정 문자열 출력, `notify.mjs`의 완료 문자열 출력이다. `unknown.mjs`는 존재하지 않는다. 주석의 테스트 명령은 실제 검증 실행의 증거가 아니며, 종료 코드만으로 게이트의 정확성·성능 효과를 주장하지 않는다.

이 검토에서는 주요 후보 중 양쪽 근거를 조건부로 설명할 수 있는 요소를 선별하고 생략한 네 후보를 ID별로 추적할 수 있다. 실제 해석에서는 조건부 득실의 관련 finding에 `inferred`·조건·검증 방법을 함께 적어야 한다. 출력 예산이 부족한 경우 반복 표현부터 줄이고 남은 후보는 `출력 예산상 생략`으로 ID와 함께 기록해야 하며, 스키마 통과만으로 전체 검토나 내용의 진실성이 보장되지는 않는다.
